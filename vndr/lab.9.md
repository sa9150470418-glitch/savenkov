2. Описание разделов технического задания согласно ГОСТ 34.602-89

🔹 Раздел 1. Общие сведения
Содержит базовую информацию о проекте:
*   Полное наименование системы и её условное обозначение
*   Шифр темы или номер договора
*   Наименования и реквизиты разработчика и заказчика
*   Перечень документов-оснований для создания системы
*   Плановые сроки начала и окончания работ
*   Сведения об источниках и порядке финансирования
*   Порядок оформления и предъявления результатов работ

🔹 Раздел 2. Назначение и цели создания (развития) системы
Состоит из двух подразделов:
*   Назначение системы: вид автоматизируемой деятельности (управление, проектирование и т.п.) и перечень объектов автоматизации
*   Цели создания системы: требуемые значения технических, технологических, производственно-экономических показателей и критерии оценки достижения целей

🔹 Раздел 3. Характеристика объектов автоматизации
Включает:
*   Краткие сведения об объекте автоматизации (или ссылки на документы)
*   Сведения об условиях эксплуатации и характеристиках окружающей среды
*   Для САПР: основные параметры и характеристики объектов проектирования

🔹 Раздел 4. Требования к системе
Самый объёмный раздел, состоит из трёх подразделов:

4.1. Требования к системе в целом:

| Подтребование | Содержание |
| --- | --- |
| Структура и функционирование | Перечень подсистем, способы связи, совместимость со смежными системами, режимы функционирования |
| Персонал | Численность, квалификация, порядок подготовки, режим работы |
| Показатели назначения | Параметры, характеризующие соответствие системы по назначению |
| Надёжность | Количественные показатели, аварийные ситуации, методы оценки |
| Безопасность | Требования при монтаже, эксплуатации, допустимые уровни воздействий |
| Эргономика и техническая эстетика | Качество взаимодействия «человек-машина», комфортность работы |
| Транспортабельность | Для подвижных АС: конструктивные требования к перемещению |
| Эксплуатация и обслуживание | Условия, регламент, требования к персоналу, хранению ЗИП |
| Защита информации | Требования по НТД отрасли заказчика |
| Сохранность информации | Перечень событий, при которых должна сохраняться информация |
| Защита от внешних воздействий | Радиоэлектронная защита, стойкость к среде применения |
| Патентная чистота | Перечень стран, для которых обеспечивается патентная чистота |
| Стандартизация и унификация | Требования к использованию стандартных решений, классификаторов, АРМ |
| Дополнительные требования | Тренажёры, сервисная аппаратура, особые условия эксплуатации |

4.2. Требования к функциям (задачам), выполняемым системой:
*   Перечень функций/задач по подсистемам, подлежащих автоматизации
*   Временной регламент реализации функций
*   Требования к качеству, точности, времени выполнения, достоверности результатов
*   Перечень и критерии отказов для функций с требованиями по надёжности

4.3. Требования к видам обеспечения:

| Вид обеспечения | Ключевые требования |
| --- | --- |
| Математическое | Состав, область применения математических методов и моделей |
| Информационное | Структура данных, обмен информацией, защита данных, СУБД, юридическая сила документов |
| Лингвистическое | Языки программирования, кодирование, диалоговые средства |
| Программное | Покупные ПО, независимость от СВТ, качество программных средств |
| Техническое | Виды ТС, функциональные и эксплуатационные характеристики |
| Метрологическое | Точность измерений, метрологическая совместимость, аттестация |
| Организационное | Структура подразделений, взаимодействие персонала, защита от ошибок |
| Методическое | Перечень НТД, стандартов, методик (для САПР) |

🔹 Раздел 5. Состав и содержание работ по созданию системы
*   Перечень стадий и этапов работ по ГОСТ 24.601 со сроками
*   Перечень организаций-исполнителей и документы, подтверждающие их участие
*   Перечень документов по ГОСТ 34.201, предъявляемых по окончании этапов
*   Порядок проведения экспертизы технической документации
*   Программа работ по обеспечению надёжности (при необходимости)
*   Работы по метрологическому обеспечению (при необходимости)

🔹 Раздел 6. Порядок контроля и приемки системы
*   Виды, состав, объём и методы испытаний системы и её частей
*   Общие требования к приёмке работ по стадиям (участники, место, сроки)
*   Статус приёмочной комиссии (государственная, межведомственная, ведомственная)

🔹 Раздел 7. Требования к подготовке объекта автоматизации к вводу системы в действие
Перечень мероприятий:
*   Приведение входной информации к виду, пригодному для обработки ЭВМ
*   Изменения в объекте автоматизации
*   Создание условий функционирования, гарантирующих соответствие ТЗ
*   Создание подразделений и служб для функционирования системы
*   Сроки и порядок комплектования штатов и обучения персонала

🔹 Раздел 8. Требования к документированию
*   Согласованный перечень комплектов и видов документов по ГОСТ 34.201
*   Перечень документов на машинных носителях, требования к микрофильмированию
*   Требования к документированию комплектующих по ЕСКД и ЕСПД
*   Дополнительные требования при отсутствии госстандартов

🔹 Раздел 9. Источники разработки
Перечень документов и материалов, на основании которых разрабатывалось ТЗ:
*   Технико-экономическое обоснование
*   Отчёты о НИР
*   Информационные материалы по системам-аналогам

🔹 Приложения к ТЗ (при наличии методик):
*   Расчёт ожидаемой эффективности системы
*   Оценка научно-технического уровня системы

3. Порядок разработки, согласования и утверждения ТЗ на АС
(согласно Приложению 1 ГОСТ 34.602-89)

📋 ЭТАП 1: Разработка проекта ТЗ
   │
   ├─ Разрабатывает организация-разработчик с участием заказчика
   ├─ Основание: технические требования, заявка, ТТЗ
   └─ При конкурсе: заказчик выбирает вариант или формирует итоговый с разработчиком

📋 ЭТАП 2: Определение необходимости согласования
   │
   ├─ Совместно заказчик и разработчик определяют органы надзора
   └─ Согласование проводится в организациях своего министерства/ведомства

📋 ЭТАП 3: Рассылка и согласование
   │
   ├─ Срок согласования в каждой организации — не более 15 дней
   ├─ Рекомендуется одновременная рассылка копий всем организациям
   └─ Замечания должны быть технически обоснованы

📋 ЭТАП 4: Работа с замечаниями
   │
   ├─ Решения по замечаниям принимаются до утверждения ТЗ
   ├─ При разногласиях составляется протокол разногласий
   └─ Конкретное решение принимается в установленном порядке

📋 ЭТАП 5: Оформление согласования
   │
   ├─ Допускается оформление отдельным документом (письмом)
   └─ При ссылке на документ делается запись под грифом «Согласованы»

📋 ЭТАП 6: Утверждение ТЗ
   │
   ├─ Утверждают руководители предприятий разработчика и заказчика
   ├─ Перед утверждением — проверка нормоконтролем и метрологическая экспертиза
   └─ Копии утверждённого ТЗ рассылаются участникам в 10-дневный срок

📋 ЭТАП 7: Внесение изменений
   │
   ├─ Дополнения согласуются и утверждаются в том же порядке
   └─ ⚠️ Изменения не допускаются после представления системы на приёмо-сдаточные испытания

📋 ЭТАП 8: Учёт и хранение
   └─ Регистрация, учёт и хранение — по ГОСТ 2.501

🔑 Ключевые требования к оформлению ТЗ:
*   Разделы располагаются в порядке, установленном разд. 2 стандарта
*   Оформление по ГОСТ 2.105 на листах формата А4 (без рамки и основной надписи)
*   Нумерация листов начинается с первого листа после титульного
*   Значения показателей указываются с предельными отклонениями или ссылками на НТД
*   Титульный лист содержит подписи заказчика, разработчика и согласующих организаций с гербовой печатью
